# PlatformAdapter Trait Specification (per docs/11-architecture.md §4)

trait PlatformAdapter {
    async fn publish_listing(&self, product: &Product, files: &[UploadFile])
        -> Result<PublishReceipt>;
    async fn update_listing(&self, listing_id: &str, patch: ListingPatch)
        -> Result<()>;
    async fn upload_digital_file(&self, listing_id: &str, file: UploadFile)
        -> Result<PlatformFileId>;
    async fn fetch_orders(&self, since: DateTime) -> Result<Vec<Order>>;
    async fn fetch_stats(&self, listing_id: &str) -> Result<ListingStats>;
    fn verify_webhook(&self, body: &[u8], headers: &HeaderMap)
        -> Result<VerifiedWebhook, VerificationError>;
    fn rate_limiter(&self) -> &RateLimiter;   // token bucket per adapter
}

## G1 ACCEPTANCE: Trait signature matches §4 verbatim (6 methods + rate_limiter).

### Supporting types:
- PublishReceipt { platform_listing_id: String, platform: String, state: ListingState, platform_raw: serde_json::Value }
- ListingPatch { title: Option<String>, description: Option<String>, price: Option<Decimal>, tags: Option<Vec<String>>, state: Option<ListingState> }
- UploadFile { filename: String, content_type: String, bytes: Vec<u8> }
- PlatformFileId { id: String, url: Option<String> }
- Order { id: String, platform: String, status: OrderStatus, total: Decimal, items: Vec<OrderItem>, buyer_email: Option<String>, occurred_at: DateTime }
- ListingStats { views: u64, favorites: u64, sales: u64, revenue: Decimal }
- VerifiedWebhook { event_type: String, platform_event_id: String, payload: serde_json::Value }
- VerificationError { reason: String }

### Common adapter infrastructure (per §4):
- Shared HTTP client (reqwest w/ rustls ≥0.23.45, S4)
- Shared TokenBucket (tower Layer)
- Shared RetryPolicy (exp backoff + jitter, max 5 attempts, only on 429/5xx)

### Security requirements (from docs/10):
- S13: Webhook signature verification mandatory on every inbound
- M5.2: Constant-time comparison for HMAC verification
- M5.4: Structured logging scrubs Authorization, Api-Key, Bearer headers
- M5.5: Adapter-level token bucket per platform
- M5.6: Proactive OAuth2 token refresh (5 min before expiry)
- M6.1: verify_webhook runs BEFORE any business logic
- M6.2: Idempotency via processed_webhook_ids cache (TTL 7 days)
- M6.6: Webhook handlers run with least privilege service account
