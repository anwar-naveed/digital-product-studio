# Per-Adapter Designs (Etsy + Lemon Squeezy + Printify + Gelato)

Each adapter implements the PlatformAdapter trait with platform-specific details per docs/11 §4, docs/09 §2, and docs/10 security requirements.

---

## 1. EtsyAdapter

### Auth Flow (OAuth2 Authorization Code + PKCE)
1. **Obtain API key** from Etsy Developer Dashboard (keystring)
2. **Redirect user** to `https://www.etsy.com/oauth/connect` with:
   - `response_type=code`
   - `client_id={keystring}`
   - `redirect_uri={configured_redirect}`
   - `scope=listings_rw files transactions_r webhooks_read`
   - `state={csrf_token}` + `code_challenge={PKCE_S256}`
3. **Receive callback** with `code` and `state`
4. **Exchange code** for tokens via `POST https://api.etsy.com/v3/public/oauth/token`:
   - `grant_type=authorization_code`
   - `code={auth_code}`
   - `redirect_uri={configured_redirect}`
   - `code_verifier={PKCE_verifier}`
5. **Store** access_token (1h), refresh_token (90d), expires_at
6. **Proactive refresh** (M5.6): background worker refreshes ≥5 min before expiry using `grant_type=refresh_token`

### Rate Limit Strategy
- **TokenBucket**: 5 req/s sustained, 10 burst (well under documented 1000/hr per shop)
- **Exponential backoff** on 429 with `Retry-After` header honored (RFC 7231)
- **Max 5 retries** before surfacing error

### Webhook Verification
- **Signature header**: `X-Etsy-Signature` (HMAC-SHA256)
- **Algorithm**: HMAC-SHA256 over raw request body using webhook secret
- **Constant-time comparison** (M5.2): use `ring::hmac::verify` or equivalent
- **Runs BEFORE persistence** (M6.1): verify in middleware/handler entry, reject 401 before DB write
- **Idempotency** (M6.2): store `processed_webhook_ids` (platform_event_id) with TTL 7 days; duplicates → 200 OK no-op
- **Least privilege** (M6.6): handler runs with service account, only enqueues job spec

### Upload Flow (per docs/09 §2.1)
1. `POST /v3/application/shops/{shop_id}/files` with multipart file → returns `file_id`
2. `POST /v3/application/listings` with `listing_files: [{file_id}]` and required fields
3. File constraints: ≤250 MB; JPG, PNG, PDF, GIF, MP4, MOV, MP3, WAV, DOC, XLS, PPT, ODT, KEY, Pages
4. Official docs: https://developers.etsy.com/documentation/tutorials/listings

### Structs
```rust
struct EtsyCredentials {
    keystring: String,
    access_token: String,
    refresh_token: String,
    expires_at: DateTime<Utc>,
    shop_id: String,
    webhook_secret: String,
}
```

## 2. LemonSqueezyAdapter

### Auth Flow (Bearer API Key)
1. **Generate API key** in Lemon Squeezy dashboard (Settings → API)
2. **Header**: `Authorization: Bearer {api_key}`
3. **No refresh flow** — rotation manual via admin console
4. **Scopes**: single key grants all resources owner manages

### Rate Limit Strategy
- **TokenBucket**: 150 req/min bucket (conservative; UNVERIFIED — public docs don't publish)
- Exponential backoff + jitter on 429

### Webhook Verification
- **Signature header**: `X-LemonSqueezy-Signature` (HMAC-SHA256)
- **Algorithm**: HMAC-SHA256 over raw body using webhook signing secret
- **Constant-time comparison** (M5.2)
- **Runs BEFORE persistence** (M6.1)
- **Idempotency** (M6.2): processed_webhook_ids cache TTL 7 days
- Official docs: https://docs.lemonsqueezy.com/api/webhooks

### Upload Flow (per docs/09 §2.2)
1. `POST /v1/products` with `attributes.delivery` type and file metadata
2. Files uploaded via signed URL or direct POST
3. Instant delivery after checkout

### Structs
```rust
struct LemonSqueezyCredentials {
    api_key: String,
    store_id: String,
    webhook_secret: String,
}
```

## 3. PrintifyAdapter

### Auth Flow (Bearer Account Token)
1. **Generate API token** in Printify dashboard (My Profile → API)
2. **Header**: `Authorization: Bearer {api_token}` (account-scoped)
3. **All shops/products** available to key owner

### Rate Limit Strategy
- **TokenBucket**: 600 req/min firm cap (R5, per docs/09 §2.3) → 8 req/s sustained, burst 20
- Exponential backoff on 429 (mandatory)

### Webhook Verification
- **Signature header**: `X-Printify-Signature` (HMAC-SHA256)
- **Algorithm**: HMAC-SHA256 over raw body
- **Constant-time comparison** (M5.2)
- **Runs BEFORE persistence** (M6.1)
- **Idempotency** (M6.2)

### Upload Flow (per docs/09 §2.3)
- Printify is POD; digital files attached via blueprint/variant config
- `POST /v1/shops/{id}/products` with blueprint ID
- No direct file upload like Etsy
- Official docs: https://developers.printify.com/

### Structs
```rust
struct PrintifyCredentials {
    api_token: String,
    webhook_secret: String,
}
```

## 4. GelatoAdapter

### Auth Flow (API Key + Optional OAuth2)
1. **Primary**: `X-API-KEY: {api_key}` header
2. **Some flows**: OAuth2 (per docs/09 §2.4)
3. **Scopes**: `products.read`, `products.write`, `orders.read`, `orders.write` (typical)

### Rate Limit Strategy
- **TokenBucket**: Conservative 4 req/s + jittered backoff (UNVERIFIED public cap)
- Exponential backoff on 429

### Webhook Verification
- **Signature header**: `X-Gelato-Signature` (HMAC-SHA256)
- **Algorithm**: HMAC-SHA256 over raw body
- **Constant-time comparison** (M5.2)
- **Runs BEFORE persistence** (M6.1)
- **Idempotency** (M6.2)
- Official docs: https://www.gelato.com/order-flow

### Upload Flow (per docs/09 §2.4)
- `POST /v1/products` with design file
- Variants for size/material
- Etsy/Shopify/Woo integrations via custom-store API

### Structs
```rust

    api_key: String,
    webhook_secret: String,
    // Optional OAuth2 fields if flow used
}
```

## Security Cross-Cutting (All Adapters)

| Requirement | Implementation |
|---|---|
| **S13/M5.2** | `verify_webhook` uses constant-time HMAC comparison; runs in handler middleware before any DB access |
| **M5.4** | Structured logging: `tracing` field filtering scrubs `Authorization`, `Api-Key`, `Bearer` |
| **M5.5** | Per-adapter `TokenBucket` as tower Layer; config via `rate_limiter()` trait method |
| **M5.6** | Etsy: background task w/ `tokio::time::interval` checks `expires_at - 5min` |
| **M6.2** | `processed_webhook_ids` cache: Redis/set in-memory with TTL 7d; key = `platform_event_id` |
| **M6.6** | Webhook handler: least-privilege service account; no admin API access; only enqueues job |
