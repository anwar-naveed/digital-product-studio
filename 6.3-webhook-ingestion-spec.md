# Webhook Ingestion Specification (per docs/11 §3, §4; docs/10 S13, M5.2, M6.x)

## Architecture Overview

Webhook ingestion is the critical path for real-time platform event processing (orders, listings, subscriptions). All 4 platforms (Etsy, Lemon Squeezy, Printify, Gelato) deliver webhooks via HTTPS POST to `/api/v1/webhooks/{platform}`.

**Core principle**: Signature verification (S13) runs BEFORE any business logic or database persistence (M6.1). This is enforced by middleware placement.

---

## Endpoint Design

```
POST /api/v1/webhooks/etsy
POST /api/v1/webhooks/lemon-squeezy
POST /api/v1/webhooks/printify
POST /api/v1/webhooks/gelato
```

**No authentication header required** — signature verification IS the authentication (per §3 webhook ingress policy).

**Request constraints**:
- Body limit: 2MB (S1, tower_http::limit)
- Content-Type: application/json (Etsy, LS, Gelato) or multipart (Printify)
- Timeout: 30s (platforms expect fast ACK)

---

## Middleware Pipeline (Exact Order)

```
1. tower_http::limit::RequestBodyLimitLayer (2MB)  [S1]
2. axum::extract::Request → raw body bytes captured
3. PlatformAdapter::verify_webhook(body, headers)  [S13, M6.1]
   - Constant-time HMAC comparison [M5.2]
   - Returns Result<VerifiedWebhook, VerificationError>
   - On Err: return 401/400 immediately, NO DB access
4. Idempotency check: processed_webhook_ids cache  [M6.2]
   - Key: platform_event_id from VerifiedWebhook
   - TTL: 7 days
   - Duplicate → 200 OK no-op
5. Enqueue job spec for worker (least privilege)  [M6.6]
   - Service account: no admin API access
   - Job types: order_created, order_paid, listing_updated, etc.
6. Return 200 OK to platform (triggers platform backoff if slow)
```

## Verify Webhook Implementation (Constant-Time)

```rust
// In each PlatformAdapter impl
fn verify_webhook(&self, body: &[u8], headers: &HeaderMap)
    -> Result<VerifiedWebhook, VerificationError>
{
    // 1. Extract signature header (platform-specific name)
    let sig_header = match self.platform() {
        Platform::Etsy => "x-etsy-signature",
        Platform::LemonSqueezy => "x-lemonsqueezy-signature",
        Platform::Printify => "x-printify-signature",
        Platform::Gelato => "x-gelato-signature",
    };
    
    let provided_sig = headers
        .get(sig_header)
        .ok_or(VerificationError::MissingHeader)?
        .to_str()
        .map_err(|_| VerificationError::InvalidHeader)?;
    
    // 2. Compute expected HMAC-SHA256 (constant-time)
    let expected_sig = self.compute_hmac(body)?;
    
    // 3. Constant-time comparison (M5.2) - NEVER use ==
    use subtle::ConstantTimeEq;
    if !bool::from(provided_sig.ct_eq(&expected_sig)) {
        return Err(VerificationError::InvalidSignature);
    }
    
    // 4. Parse and validate payload
    let payload: serde_json::Value = serde_json::from_slice(body)
        .map_err(|_| VerificationError::InvalidJson)?;
    
    // 5. Extract platform_event_id for idempotency
    let platform_event_id = self.extract_event_id(&payload)
        .ok_or(VerificationError::MissingEventId)?;
    
    // 6. Extract event_type
    let event_type = self.extract_event_type(&payload)
        .ok_or(VerificationError::MissingEventType)?;
    
    Ok(VerifiedWebhook {
        event_type,
        platform_event_id,
        payload,
    })
}

fn compute_hmac(&self, body: &[u8]) -> Result<String, VerificationError> {
    use ring::hmac;
    let key = hmac::Key::new(hmac::HMAC_SHA256, self.webhook_secret().as_bytes());
    let sig = hmac::sign(&key, body);
    Ok(hex::encode(sig.as_ref()))
}
```

**Critical**: Uses `subtle::ConstantTimeEq` or `ring::hmac::verify` for constant-time comparison. Never `==` or `==` on strings.

## Idempotency Layer (M6.2)

```rust
// In webhook handler, AFTER verify_webhook succeeds
async fn handle_webhook(
    State(state): State<AppState>,
    body: Bytes,
    headers: HeaderMap,
) -> Response {
    // ... verify_webhook ...
    
    // Check idempotency cache
    let cache_key = format!("webhook:{}:{}", platform, verified.platform_event_id);
    let mut cache = state.webhook_cache.lock().await;
    
    if cache.contains_key(&cache_key) {
        // Duplicate - return 200 OK no-op
        return (StatusCode::OK, "duplicate").into_response();
    }
    
    // Insert with TTL 7 days
    cache.insert(cache_key, Instant::now() + Duration::days(7));
    drop(cache);
    
    // Enqueue job for worker (least privilege)
    state.job_queue.enqueue(JobSpec {
        tool: "webhook-processor",
        args: json!({
            "platform": platform.to_string(),
            "event_type": verified.event_type,
            "payload": verified.payload,
        }),
    }).await?;
    
    (StatusCode::OK, "accepted").into_response()
}
```

## Worker Job Spec (Webhook Processor)

```json
{
  "tool": "webhook-processor",
  "subcommand": "run",
  "args": {
    "platform": "etsy|lemon-squeezy|printify|gelato",
    "event_type": "order_created|order_paid|...",
    "payload": { /* verified webhook payload */ }
  },
  "timeout_secs": 60,
  "expected_outputs": ["order_processed", "listing_updated"]
}
```

**Worker actions** (least privilege, M6.6):
1. Parse payload → domain events
2. Update `platform_listings` state machine (§2 Listing state machine)
3. Insert `sales_events` rows (gross, fee, net per fee_tables)
4. Update inventory/stock if applicable
5. Emit audit event (M1.3) with correlation_id
6. **No admin API calls** — only DB writes via service account

## Rate Limiting & Backpressure (S10, M6.5)

- **Pingap**: `limit_req_zone` per IP (platform webhook IPs known)
- **pipeline-core**: bounded channel (1000 pending) for async processing
- **Backpressure**: returns 503 to platform → triggers exponential backoff
- **Worker concurrency**: semaphore per tool-class (cf-image-gen=2, etc.)
