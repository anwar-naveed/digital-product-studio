## Implementation Details

### PlatformAdapter Trait Implementation (6 methods + rate_limiter)
1. `publish_listing()` - Two-step flow: upload files → create listing with file_ids
2. `update_listing()` - PUT /v3/application/listings/{listing_id}
3. `upload_digital_file()` - POST /v3/application/shops/{shop_id}/files
4. `fetch_orders()` - GET /v3/application/shops/{shop_id}/receipts
5. `fetch_stats()` - GET /v3/application/listings/{listing_id}/stats
6. `verify_webhook()` - HMAC-SHA256 with constant-time comparison (M5.2)
7. `rate_limiter()` - TokenBucket: 5 req/s sustained, 10 burst

### Security Requirements (from docs/10)
- S13: Webhook signature verification mandatory - implemented in verify_webhook()
- M5.2: Constant-time comparison using `subtle::ConstantTimeEq` / `ring::hmac::verify`
- M5.4: Structured logging with `tracing` - auth headers not logged
- M5.5: Per-adapter TokenBucket as tower Layer - implemented in RateLimiter
- M5.6: Proactive OAuth2 token refresh (≥5 min before expiry) - EtsyTokenRefresher
- M6.1: verify_webhook runs BEFORE any business logic - trait method design enforces this

### Etsy-Specific Features (per 6.3-per-adapter-designs.md)
- OAuth2 Authorization Code + PKCE flow
- Token refresh using refresh_token grant
- Rate limiting: 5 req/s sustained, 10 burst (well under 1000/hr)
- Exponential backoff with Retry-After header honored
- Webhook signature header: X-Etsy-Signature (HMAC-SHA256)
- File constraints: ≤250 MB, validated allowed MIME types
- Shop-scoped operations
