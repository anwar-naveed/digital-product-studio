# 7.3-jailspec-s3-delivery

## Summary

Successfully implemented **command-spec validators (S14 jail)** and **S3 staging layer** for the digital-product-studio pipeline-core service.

## Files Created/Modified

### New Source Files

1. **pipeline-core/src/jobspec/mod.rs** - Command-spec validator implementing S14 injection jail
   - `JobCommandSpec` - Validated job command specification with JSON Schema
   - `ValidatedJobTool` - Allowlisted tools (cf-image-gen, photocraft-cli, vectorcraft-cli)

     - Subcommand allowlists per tool

   - `WorkerS3Client` - Upload operations (generation, product bundles, mockups, tmp staging)
   - `AdminS3Client` - Curation flow (presign preview, approve copy raw→curated, product/listing/mockup presigns)
   - `S3ClientFactory` - Environment-based client creation

3. **pipeline-core/tests/jobspec_validation_tests.rs** - Fuzz-style unit tests (G1)

     - Unknown tools
     - Timeout bounds (0, >1800)
     - Symlink-like patterns
     - Current directory references (`.`)
     - Control characters
   - Zero-shell-interpolation verification (G2)
   - Path confinement validation
   - All allowlisted subcommands verified

4. **pipeline-core/tests/s3_tests.rs** - S3 key builder tests (G3) + MinIO integration tests (G4)

## Security Compliance (S14)

- **Never shell-interpolate**: JSON args passed via structured `Vec<String>` to `Command::arg().arg()`
- **Params file**: Large JSON payloads written to `/workspace/params/job-<uuid>.json` and passed via `--params-file` (M2.2)
- **Path confinement**: Input/output paths canonicalized and verified under `--automation-read-root=/workspace/read` and `--automation-write-root=/workspace/write`
- **Allowlist validation**: Subcommands validated against per-tool allowlists (858 photocraft, 732 vectorcraft commands)
- **Adversarial rejection**: Path traversal, absolute paths, shell metacharacters, symlinks, control chars all rejected
